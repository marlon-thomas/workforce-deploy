# Care Angels Workforce — Deployment Machinery

**Public, single source of the deployment apparatus** (ADR-0010). Everything
needed to install, update, heal and operate a Care Angels appliance lives in
this repository. The application source is closed: **versioned images are
published to GHCR** and require a GitHub `read:packages` PAT — the same token
the installer prompts for, and the licensing control point for customers.

You do NOT need the private source repo to deploy or operate the product.

## Layout

| Path | What |
|---|---|
| `bin/bootstrap.py` | first-command runner: preps a fresh box (root or Vagrant), ships out-of-band host files, runs the installer |
| `bin/install.sh` | the appliance installer (service user → rootless Docker → prompts → Ansible) |
| `bin/update.sh` / `doctor.sh` / `backup.sh` / `smoke.sh` | versioned updates with rollback, health check, backups, OIDC-less smoke run |
| `bin/deploy_to_test.py` | laptop orchestrator for the TEST VM lifecycle (Vagrant + Tailscale + DuckDNS + installer) — run it from a clone of this repo |
| `bin/gen-test-ca.sh` | workstation-only: private test CA (TLS for the test env never touches a public CA) |
| `compose.yaml` + `gateway/` `blueprints/` `ansible/` | the declarative stack: Caddy (TLS), authentik (OIDC), the suite |
| `environments/*.env` | per-environment names/TLS mode + the **pinned app version** |
| `host-setup/setup-host.py` | the ONLY privileged host prep (idempotent; invoked automatically by deploy_to_test when a gap is detected) |
| `RUNBOOK.md` | day-2 operations |

## Quick start

**Test appliance (any dev box with Vagrant + libvirt):**
```bash
bin/gen-test-ca.sh test            # once per machine (prints the trust-import line)
python3 bin/deploy_to_test.py      # VM → Tailscale/DuckDNS → installer (self-heals host prep via sudo)
```
Then browse `https://workforce-test.duckdns.org` (sign-in served at
`…-auth.duckdns.org`); the first account to sign in creates the organisation
through the first-run wizard and becomes its administrator.

**Production VPS:**
```bash
python3 bin/bootstrap.py --host <ip> --env prod
```
(prod uses real Let's Encrypt via HTTP-01; `test` never issues public certificates.)

## Credentials & secrets

Nothing secret is committed here. Out-of-band files the deploy expects on the
workstation: `~/.config/workforce-dev/duckdns.env` (test DNS records) and
`~/.config/workforce-dev/testca/` (test CA material, generated by
`gen-test-ca.sh`). GHCR pull credentials and the appliance's own secrets live
on the target machine (service user's `~/.docker/config.json`,
`secrets/`) — never in git.

## Versioning

* suite images: `ghcr.io/marlon-thomas/workforce-suite:<semver>` (private; PAT)
* this repo is tagged `v<major>.<minor>` for apparatus releases; `environments/*.env`
  pins which app version each environment runs

## Operator runbook — build, then deploy

Build and deploy are discrete: the build pipeline only publishes packages to
GHCR; deploys only pull a published package onto a box. Nobody needs repo
write access to deploy — the deploy scripts run from a clone of this repo.

**1. Build (publishes to GHCR, touches no machine)**
   * release: `git tag v0.2.16 && git push --tags` in the private source repo
   * manual/snapshot: Actions → *publish* → Run workflow (optional `version` input)
   * the run summary prints the exact version string

**2. Deploy to TEST** — `python3 bin/deploy_to_test.py`
   boots/checks the appliance, installs or resumes, then CONVERGES it to
   `environments/test.env:APP_VERSION` (update.sh; backup + health check +
   auto-rollback) and verifies `/api/v1/build-meta`. The test pin is bumped
   automatically by release publishes (or `gh workflow run bump-test-pin.yml`).

**3. Deploy to PROD** — `python3 bin/deploy_to_prod.py`
   same shared converge/verify code (bin/deploylib.py) against the box in
   `ansible/inventories/prod/hosts.yml`, converging to
   `environments/prod.env:APP_VERSION`. The only differences are
   environment-specific (no VM/tailnet; real TLS). Prod deploys always ask
   you to TYPE the version before changing anything. Bumping prod.env is a
   deliberate commit — that commit IS the sign-off.

**4. Find versions** — on either box: `./bin/versions.sh` (newest first).
